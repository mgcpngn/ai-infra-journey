# 怎么手动运行 dpo_poem.py

代码：[dpo_poem.py](dpo_poem.py)（用户本地 /home/wangli/step1/dpo_poem.py，10-20 上传）。下面的行号都指这个文件。

## 1. 运行之前要有的东西
- 同一个文件夹里要有 `lora_poem.py`。第 17～18 行会读它，只执行到「# ---------- 1. 基线」之前（读数据、`encode`、`generate_all` 这些工具）。所以 L=64 这类设置来自 lora_poem.py 第 28 行。
- 要有第 6 步存下的 LoRA：`checkpoints/qwen3_0.6b_lora_r8`（第 21 行）。

## 2. 运行
```bash
cd /home/wangli/step1
python dpo_poem.py
# 连不上 Hugging Face 时：HF_ENDPOINT=https://hf-mirror.com python dpo_poem.py
```
结果写进 `results_dpo.md`（第 18 行把文件名换掉了）。

## 3. 屏幕上看哪一行
训练时每 50 步，第 133 行打印一行，例如：
```
step 50  loss=0.5682  选对率(200 对)=54.0%  509 ms/步  显存峰值 5.09 GB
```
- **509 ms/步** 就是从这里来的。第 107 行开始计时，第 129 行结束计时，只算训练这一步；第 131 行测选对率的时间不算在里面。第 132 行把 50 步的时间加起来再除以 50。
- 同一个数也在 results_dpo.md「实验 2」表的「每步耗时 ms」那一列。

## 4. 一步里面发生了什么（第 106～129 行）
| 行 | 做什么 |
|---|---|
| 109 | 随机挑 BS=8 对诗的编号 |
| 111 | 把 8 首 chosen 和 8 首 rejected 拼在一起：一共 16 首 |
| 114～115 | **旧模型**读这 16 首（同一个模型临时关掉 LoRA，`no_grad`：不算梯度） |
| 117 | **新模型**读同样的 16 首（LoRA 打开，要算梯度） |
| 120～123 | 算 loss：新模型比旧模型，在 chosen 上抬高得要比在 rejected 上多 |
| 125 | 算梯度 |
| 126 | 按学习率改 LoRA 的参数 |

所以 DPO 每一步：16 首诗被读 2 遍（一遍不算梯度，一遍算梯度）。第 6 步 LoRA 每一步：16 首诗被读 1 遍（算梯度，lora_poem.py 第 256 行）。实测 509 ms 比 370 ms 多，原因是多读的那一遍（推测，没有单独测过）。

注意：第 4 行和第 114 行写明，这里的旧模型是**关掉 LoRA 的基础模型**，不是第 6 步训练好的 LoRA 模型。标准 DPO 一般用训练起点（这里就是第 6 步的 LoRA 模型）当旧模型。第 136 行的注释也说了这一点。

## 5. 可以改的参数（都在第 20 行）
| 参数 | 现在的值 | 意思 |
|---|---|---|
| `BS` | 8 | 每一步几对诗（实际读 2×BS 首） |
| `LR` | 5e-6 | 学习率，整个训练不变（第 100 行，没有预热） |
| `STEPS` | 300 | 训练多少步。请用 50 的倍数，不然最后几步不打印 |
| `BETA` | 0.1 | 允许离旧模型多远。越大，离旧模型越近 |

想先快速看一下：把 `STEPS` 改成 50，只会打印一行 step 50。

## 6. 「每个字 129 ms」从哪里来
- results_dpo.md「实验 4」表，「每字平均生成时间」那一行，训练前 129.4 ms。
- 第 92 行调 `timed_gen`（第 77～84 行）：生成 10 首诗的总时间 ÷ 生成的汉字个数（241 个）。它用的是 lora_poem.py 里的 `generate_all`，一次写一个字，没有 vLLM 的那些办法。
