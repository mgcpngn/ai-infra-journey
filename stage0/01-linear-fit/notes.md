# 第 1 步笔记：梯度下降拟合直线

**一句话**：整个脚本是在给 100 个已知答案的点，找一条最贴近它们的直线 y = w·x + b。程序事先不知道答案是 w=3、b=2，只能靠训练自己找出来。

互动演示：[labs/gradient-lab.html](../../labs/gradient-lab.html)

## 训练循环：每一步做的 4 件事

1. **前向**：用**当前的** w、b，对每个点算出预测值 w·xᵢ + b
2. **算 loss**：每个点的偏差 = 预测 − 已知的 yᵢ。100 个偏差各自平方，加起来再除以 100，就是 loss（均方误差 MSE）。loss 只打分，不改任何参数
3. **反向传播**：算出 loss 对每个参数的梯度，也就是每个参数往哪边拧、loss 会变小。这一步也不改参数
4. **更新**：w = w − 学习率 × 梯度，b 同理。这一步才真的改参数

循环到 loss 不再下降为止。目标是 loss 最低，不一定是 0：数据带噪声，这里最终停在约 0.011。

推理只做第 1 件事：w、b 已经训练好，给一个新 x，直接算 y。**推理 Infra 研究的，就是怎样把这一步做得又快又省。**

## 我问过的问题

**loss 怎么知道正确的值是多少？**
loss 从来不知道正确的 w、b，只知道每条数据的正确答案 y。它拿预测和这些已知答案比。大模型训练时，「正确答案」就是文本里真实的下一个字，所以海量文本本身就是答案，不用人工标注。

**初始的 w、b 谁定？**
写代码的人。这里是 0。神经网络一般用很小的随机数开头（全设成 0 的话，所有神经元会一模一样）。微调大模型时，用别人训练好的权重当初始值。

**反向传播为什么叫「反向」？**
它用链式法则，从 loss 一路往回推到参数：先算 loss 对预测有多敏感（2 × 偏差），再算预测对 w 有多敏感（x），两者相乘就是 loss 对 w 的梯度。计算方向和前向相反，所以叫反向。

**怎么保证调整方向是让 loss 变小？**
不是「把预测调小」，而是让预测**往已知的 y 靠拢**。例子：x=1、y=5、w=0，预测 0 偏低，梯度 = 2 × (−5) × 1 = −10，更新 w = 0 − 0.1 × (−10) = 1，新预测 1 更接近 5。预测偏高时梯度变正，减掉之后 w 变小。「减梯度」总是把预测往答案推。

**学习率是什么？**
每一步迈多大。梯度只说往哪走、坡多陡；学习率决定真的走多远。

| 学习率 | 现象 |
| --- | --- |
| 0.001 | 太小，200 步还远没到谷底 |
| 0.1 | 稳定收敛 |
| 0.9 | 更快，但 b 在谷底两侧来回弹，离发散很近 |
| 1.5 | 每步都跨过谷底，落到更高的对面，越跳越高，最后数值溢出 |

**手工算梯度 vs 自动求导？**
结果一模一样。手工是自己用微积分推公式；自动是 PyTorch 记下每步运算，`loss.backward()` 时按链式法则倒推。对比是为了确认 `backward()` 没有魔法。80 亿参数的模型没法手推，全靠它。

**float64 是什么？**
每个数占 8 字节。大模型训练用 bf16（2 字节），推理还会压到 int8、int4。位数越少越省显存、越快，但越不精确。这就是「量化」，推理 Infra 最重要的旋钮之一。

## 过关题与我的回答

| 题 | 我的回答 | 批改 |
| --- | --- | --- |
| 训练每步做哪 4 件事 | 前向、算 loss、算梯度、更新 | 通过。第一步是用当前 w、b 算预测，不是「算 w、b」 |
| lr=1.5 为什么发散 | 步子迈大了，跨过正确答案，错得越来越远 | 通过。「溢出」是结果，原因是越过谷底后坡更陡、下一步迈得更远 |
| 推理时哪些还需要 | 第一次答错；第二次：w、b 已有，给 x 直接算 y，不用再「尝试」 | 通过。loss、梯度、更新、学习率、步数推理都不需要 |

## 和大模型的对应关系

| 概念 | 这个脚本 | 8B 大模型 |
| --- | --- | --- |
| 参数 | w、b 两个数 | 约 80 亿个数，bf16 下约 16GB |
| 前向 | w·x + b | 几十层矩阵乘法（GEMM） |
| loss | 均方误差 | 交叉熵 |
| 梯度与更新 | 手推或 backward() | backward() + 优化器 |
