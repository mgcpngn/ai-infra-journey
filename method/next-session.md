# 下一次学习素材：从“跑过”到“解释清楚”

准备日期：2026-11-12。承接 `difficulty.md` 中 11-10 的待答主题。下面是教练选题素材，每次只向用户呈现一题；不是已完成记录。用户回答后，更新难度和接续状态，不机械重复本清单。

## 开场

上次已经完成参数 fp8 和 KV cache fp8 的实验。这次先检查你怎样解释这些现象，再选一个你想验证的问题。回答可以很短，分成思路、过程、结果；不用计算。

## 题 1：只有一个答案的一组

同一道题，一组只让模型写一个答案。检查程序给它 1 分，再减去这一组的平均分。最后剩多少？如果给的是 0 分呢？你觉得这一组还提供了什么加强或减弱的信号？

教练准备：读 `stage0/09-rl/adv_demo.py` 的 D、E 和 `labs/rl-one-question.html`。如不会，先看袋子游戏，只观察一次变化；不要把这个小实验的结论扩大到所有 RL 方法，也不要未经检查就承诺实际程序的全部参数绝对不变。

## 题 2：写第 100 个 token

模型已有前面 99 个 token 的 KV cache。要写下一个 token 时，前面 99 个 token 的 K、V 需要重新算吗？已经存好的 K、V 还需要被读取吗？请分开说明理由。

教练准备：用 `labs/one-word-time.html` 的第 0 关和第 1 关建立“参数、KV cache、计算”的对应；注意“不重算”与“不读取”是两件事。

## 题 3：人多了以后搬什么

打开 `labs/one-word-time.html` 的第 1 关。保持其他设置不变，只增加用户数。先预测蓝色和橙色哪一个变化更多，再拖动观察。什么时候橙色比蓝色长？两种颜色各表示什么？

教练准备：先读页面源码确认颜色和初始参数，记录用户实际设置与观察；解释网页是简化估计，不能直接作为实际服务承诺。

## 题 4：temperature 改变了什么

同样的输入、同样的模型参数，只把 temperature 从 1 改成 0.5。你预测选择下一个 token 时会更集中还是更分散？这次请求有没有因此训练并修改模型参数？为什么？

教练准备：结合 11-09 日志，只检查用户能否区别生成时的选择与训练时的改参数；不额外引入一串采样方法。

## 题 5：怎样知道是谁起作用

假设餐馆同时换了厨师和炉子，出菜快了。能直接认定全是炉子的功劳吗？你会怎样安排一次对照？再把你的办法用到“换注意力算法、KV cache 转 fp8”的实验上。

教练准备：读 `stage1/03-vllm-fp8-kv/results.md` 的三次对比；用户能提出一次只改一项后，再讨论重复测量的作用。不把一次结果中的“一半一半”讲成固定比例。

## 复习后的实验入口

让用户填三句话：“这次我要回答……”“我预测……”“因为……”。根据回答选择一个最小实验，给出已有运行说明和要看的输出。机械执行交给脚本，等待时不另塞新概念。跑完由用户对照预测，最后用自己的话写收获。
