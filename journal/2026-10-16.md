## 复习批改（3 对 2 半对）
1. ✅ embedding/输出层不变——只由字表大小和 384 决定。
2. ✅ 过拟合；办法：加数据 / 减参数（另：早停）。

4. ⚠️ "复用启动"要改：batch=1 时时间 ≈ 启动次数 × 启动开销；KV cache 只减计算、不减启动次数，所以不提速；batch 大时计算是大头（第 5 步：batch=1 0.9×，batch=128 15×）。
5. ✅ 搬数据时间减少（算子融合减少显存读写）。

## 干净对照：--compile（唐+宋，2 块，各 1000 步）
| | 稳定段 token/s | 验证 loss |
|---|---|---|
| 不加 | ~17.5 万（200～700 步） | 5.35 |
| 加 | ~21.2 万 | 5.32 |
- 约 1.2×，低于预测的 1.3～1.5×。推测：gpt_tang.py 每步还有取数据、改学习率、清梯度、裁剪、AdamW 等未编译部分，摊薄了收益（graph_test 只测训练步）。
- 不加那次最后几百步 17.7 万 → 12.8 万：疑似笔记本 GPU 发热降频（推测）→ 比速度看稳定段。
- 加 compile 那次生成变慢（15～31 ms/字 vs 2～4 ms）：怀疑本地 generate 走了编译模型、每种新长度重编译，待本地 Claude Code 检查。
- 结论：训练超过 1000 步就加 --compile，省 15%～20%。
