# 第 4 步笔记：小 GPT 写唐诗

## 实测结果（RTX 4060 Laptop 8GB，默认配置：6 层、6 头、384、block 128、5000 步）

- 词表：8,182（和第 3 步同一份）
- 参数量：16,980,480，约 1700 万，**只有 bigram（66,945,124）的约 1/4**
- 训练前 loss：9.1513，接近瞎猜的 ln(8182) ≈ 9.01，说明初始化正常
- 训练速度：每秒 8～10 万 token
- 生成速度：每秒约 100 个字

| 步数 | 训练 loss | 验证 loss |
| --- | --- | --- |
| 0 | — | 9.15 |
| 500 | 5.12 | 5.53 |
| 2000 | 4.00 | 4.83 |
| 3500 | 3.55 | **4.78**（最低） |
| 5000 | 3.34 | 4.80 |

## 读这张表

- **结构比参数量重要。** 第 500 步验证 loss 5.53 就已经低于 bigram 练到头的 6.44。最好时 4.78，困惑度 e^4.78 ≈ 119，bigram 是 e^6.44 ≈ 626：相当于每个字从"在 626 个字里猜"缩小到"在 119 个字里猜"。参数却只有 bigram 的 1/4。bigram 只看前一个字，GPT 用注意力能看前面 128 个字。
- **3500 步之后开始轻微过拟合。** 训练 loss 继续降（3.55 → 3.34），验证 loss 不降反升（4.78 → 4.80）。最好的停点在 3500 步左右，这就是早停。
- **训练快、生成慢。** 训练每秒 8～10 万 token，生成每秒约 100 个字，差约 1000 倍。训练时一个 batch 里所有位置同时算；生成时下一个字要等上一个字出来，只能一次算一个。

## 还没解决的

- **生成的诗还数不对五言、七言。** 可能的原因：模型小、只练了 5000 步；全唐诗里混着杂言、词、长短句，格式本身不统一。明天可以看几首具体样本再判断。
