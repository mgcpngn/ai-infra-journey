# 第 4 步笔记：小 GPT 写唐诗

## 实测结果（RTX 4060 Laptop 8GB，默认配置：6 层、6 头、384、block 128、5000 步）

- 词表：8,182（和第 3 步同一份）
- 参数量：16,980,480，约 1700 万，**只有 bigram（66,945,124）的约 1/4**
- 训练前 loss：9.1513，接近瞎猜的 ln(8182) ≈ 9.01，说明初始化正常
- 训练速度：每秒 8～10 万 token
- 生成速度：每秒约 100 个字

| 步数 | 训练 loss | 验证 loss |
| --- | --- | --- |
| 0 | — | 9.15 |
| 500 | 5.12 | 5.53 |
| 2000 | 4.00 | 4.83 |
| 3500 | 3.55 | **4.78**（最低） |
| 5000 | 3.34 | 4.80 |

## 代码导读：[gpt_tang.py](gpt_tang.py)

| 位置 | 做什么 |
| --- | --- |
| `CausalSelfAttention` | 一个线性层算出 Q、K、V → 拆成多个头 → `q @ kᵀ / √hs` 打分 → 下三角遮罩 → softmax → 加权求和 V → 输出投影 |
| `MLP` | 384 → 1536 → GELU → 384 |
| `Block` | `x = x + attn(ln1(x))`，`x = x + mlp(ln2(x))`：先 LayerNorm 再算，结果加回去（残差） |
| `GPT` | 字表 + 位置表 → 6 个 Block → 最终 LayerNorm → 输出层（384 → 8182，无偏置）；权重用 std=0.02 的正态分布初始化 |
| `generate` | 没有 KV cache：每个字都把最多 block_size 个前文整个重算 |
| 第 4 段 | 按名字把参数归成 embedding / 注意力 / MLP / 输出层四组，就是你贴的那张分布表 |
| 第 5 段 | 训练细节，前几步没用到的新东西都在这里，见下 |
| 第 8 段 | 把权重、结构参数、词表一起存进 `checkpoints/gpt_tang.pt`，第 5 步直接加载 |

**第 5 段里的训练技巧**（以后训练大模型都会用到）：
- **dropout 0.1**：训练时随机丢掉 10% 的数，防止死记硬背；评估和生成时关掉（`model.eval()`）。
- **学习率预热 + 余弦下降**：前 100 步从 0 慢慢升到 1e-3，之后按余弦曲线降到 1e-4。一开始参数是随机的，步子太大容易跑偏；快结束时步子小一点，停得更稳。
- **weight decay 0.1**：每步把参数往 0 拉一点点，也是防过拟合。
- **梯度裁剪 1.0**：梯度总大小超过 1 就按比例缩小，防止偶尔一步把模型带崩。
- **bf16 混合精度**：矩阵乘用 2 字节的 bf16 算，参数和梯度仍是 4 字节，又快又不丢精度。

## 读这张表

- **结构比参数量重要。** 第 500 步验证 loss 5.53 就已经低于 bigram 练到头的 6.44。最好时 4.78，困惑度 e^4.78 ≈ 119，bigram 是 e^6.44 ≈ 626：相当于每个字从"在 626 个字里猜"缩小到"在 119 个字里猜"。参数却只有 bigram 的 1/4。bigram 只看前一个字，GPT 用注意力能看前面 128 个字。
- **3500 步之后开始轻微过拟合。** 训练 loss 继续降（3.55 → 3.34），验证 loss 不降反升（4.78 → 4.80）。最好的停点在 3500 步左右，这就是早停。
- **训练快、生成慢。** 训练每秒 8～10 万 token，生成每秒约 100 个字，差约 1000 倍。训练时一个 batch 里所有位置同时算；生成时下一个字要等上一个字出来，只能一次算一个。

## 参数量分布（上下文改成 256 之后）

总数 17,029,632（float32 约 65 MB）。我按公式核对过，每一项都对得上：

| 部分 | 参数量 | 占比 | 怎么来的 |
| --- | --- | --- | --- |
| embedding（字 + 位置） | 3,240,192 | 19.0% | 8182×384 + 256×384 |
| 注意力（6 层） | 3,552,768 | 20.9% | 每层 QKV 384×1152 + 输出 384×384，加偏置和 LayerNorm |
| MLP（6 层） | 7,094,016 | 41.7% | 每层 384→1536→384，加偏置和 LayerNorm |
| 输出层（ln_f + head） | 3,142,656 | 18.5% | 384×8182，加 LayerNorm |

- **MLP 最大**，约是注意力的 2 倍：每层 MLP 有 2×384×1536 个 w，注意力只有 4×384×384 个。
- **上下文从 128 改到 256，参数只多了 49,152 个**（位置表多 128 行）。上下文长度几乎不影响参数量，影响的是计算量和显存（第 5 步的 KV cache 会看到）。
- **embedding 和输出层加起来占 37%**，因为词表 8182 相对这个小模型很大。真实 LLM 里 MLP 占得更多。

## 生成的诗（温度 0.8）

```
春风兮雪兮消息，柳花落兮人寂寥。玉京君兮不可从，梦君君兮万里遥。
月明，山中犹有鹿门声。此时独坐斜阳里，犹有人间多白生。
山中。须臾落第堪垂泪，不为同心作故人。
风落凤池上，寒露滴兰丛。
花照水，烟花水阁卷旌旗。风飘丽句惭无敌，酒竭平津逞胜诗。清夜思量旧才薄，更随将使胜公时。
```

**其实已经数对了。** 一句一句数：「此时独坐斜阳里」「犹有人间多白生」「须臾落第堪垂泪」「风飘丽句惭无敌」都是 7 个字，「风落凤池上，寒露滴兰丛」是 5 个字。看起来乱，是因为每首诗的开头是从半句开始的（「月明，」「山中。」「花照水，」），后面就整齐了。第一首是带「兮」的楚辞体，也是每句 7 个字，还押了韵（寥、遥）。

**bigram 做不到、GPT 能做到的原因**：要知道"这里该放逗号了"，得数出这一句已经写了几个字。bigram 只看前一个字，没法数；GPT 用注意力能看到这一句前面的所有字，还有位置编码告诉它每个字在第几位。

## 问题 5：为什么生成越长，每个字并没有变慢

没有 KV cache 时，每生成一个字都把窗口里的字全部重算一遍，按理越往后越慢。实际每个字都是 8～9 ms，有两个原因：

1. **窗口有上限。** 模型最多看 256 个字，超过以后每一步都只重算最后 256 个字，工作量不再增长。
2. **模型太小，GPU 在空等。** 每生成一个字要启动约上百个小 GPU 算子。这么小的模型，一次算 10 个字还是 256 个字，GPU 都是一眨眼算完，时间主要花在"启动算子"上，跟第 2 步 batch 很小时一样，是 launch-bound。所以重算多少个字，耗时差不多。

50 字（9.27 ms）比 500 字（8.96 ms）还慢一点、200 字最快（8.22 ms），这些差距在 10% 以内，属于测量波动。50 字那次很可能还包含了 GPU 第一次运行的预热时间（推测，没有单独验证）。

**这对第 5 步的意思**：KV cache 省的是"重算"，而这个小模型重算本身不花时间，所以 batch=1 时 KV cache 可能几乎不提速。要看到它的作用，得让计算量变大：一次生成很多条（batch 大），或者放到 CPU 上跑。第 5 步会专门测这个。
