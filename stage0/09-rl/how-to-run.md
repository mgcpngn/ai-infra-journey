# 第 9 步：RL 后训练（检查程序打分）

代码：[rl_poem.py](rl_poem.py)。下面的行号都指这个文件。

## 1. 和第 8 步比，多了什么、少了什么

| | 第 8 步 train_loop.py | 第 9 步 rl_poem.py |
|---|---|---|
| 数据 | 16 首真唐诗（标准答案） | 没有标准答案，只用题目和体裁 |
| 每一步 | 读 16 首，学着猜下一个字 | 给 1 个题目，模型**自己写** 16 首 |
| 谁判断好坏 | 标准答案 | 检查程序 `reward_of`（第 48～55 行）给分 |
| 起点 | 新 LoRA | 新 LoRA（没经过第 6 步），一开始几乎写不对格式 |

**打分规则**（第 48～55 行）：4 句、每句字数对（五言 5 字、七言 7 字）得 1 分。前 4 句里每句对一句得 0.25；每多写一句扣 0.25；最低 0 分。

## 2. 运行

```bash
cd ~/ai-infra-journey-git
git pull
cd stage0/09-rl
python rl_poem.py
```
要用到 `../08-train-loop/poems.csv`（git pull 以后就有）。100 步大约几分钟（推测）。

## 3. 程序的结构

| 行 | 做什么 |
|---|---|
| 20～29 | 可以改的参数 |
| 48～55 | 打分规则 |
| 76～88 | `write`：给一个题目写 n 首诗 |
| 91～96 | 训练前：6 个固定题目（3 个五言、3 个七言）各写 1 首 |
| 105～108 | 环节 1：挑题目 |
| 110～112 | 环节 2：写诗。同一个题目写 16 首（这一步就是推理） |
| 114～117 | 环节 3：打分。每首的分数减去这一组的平均分 |
| 119～128 | 环节 4：猜下一个字。模型重新读一遍自己写的 16 首 |
| 130～132 | 环节 5：算梯度 |
| 134～138 | 环节 6：改参数 |
| 151～ | 汇总（含按体裁分开的平均分），然后训练后再写一遍那 6 个题目 |

**环节 3 是关键**：16 首里比平均分高的，得到正数；比平均分低的，得到负数。环节 4 的 loss 让正数那几首里的 token 更容易被写出来，负数那几首更不容易。

## 4. 屏幕上看哪一行

- 每一步一行：`step 体裁 平均分 全对 | 6 个环节各自的 ms 合计 | 显存峰值 MB`。「平均分」是这一组 16 首的平均分，「全对」是 16 首里得 1 分的占多少。
- 每 10 步多一行：这一组里得分最高的那一首。
- 汇总：前 10 步和最后 10 步的平均分、全对比例；6 个环节各占多少时间；显存峰值。
- 最后：同样 6 个题目（3 个五言、3 个七言）、同样的随机种子，训练后写出来的诗。

## 5. 运行之前，请先预测（不用算）

1. 6 个环节里，哪个花的时间最多？
2. 平均分会从前 10 步到最后 10 步涨上去吗？
3. 显存峰值比第 8 步（5468 MB）高还是低？

## 6. 跑完以后，一次只改一个参数

| 改什么 | 改成 | 先预测 |
|---|---|---|
| `BALANCE` | True | 五言、七言轮流出题，训练后五言题目还会写成七言吗？ |
| `G` | 8 | 写诗的时间会变成一半吗？ |
| `TEMP` | 0.5 | 16 首会更像还是更不像？平均分涨得更快还是更慢？ |
| `NEW` | 24 | 七言绝句还写得完吗？ |

# 第 9b 步：RL 后训练（算术题，Python 检查答案）

代码：[rl_math.py](rl_math.py)。下面的行号都指这个文件。

## 1. 和第 9 步（写诗）比

| | 第 9 步 rl_poem.py | 第 9b 步 rl_math.py |
|---|---|---|
| 题目 | 诗的题目和体裁 | 两位数的加法或乘法，比如 `37×46=`（第 48～51 行） |
| 打分 | 数句子的字数，有部分分 | 第一个数等于正确答案得 1 分，否则 0 分（第 54～57 行） |
| 对不对 | 格式对，不代表诗好 | 答案对就是对，没有「看起来对」 |
| 每个答案多长 | 最多 48 个 token | 最多 8 个 token（`NEW`） |
| 训练前后怎么比 | 6 个题目各写 1 首 | 100 道固定的题考试，数对了几道（第 96～107 行） |

6 个环节和 loss 和第 9 步一样（第 111～161 行）。

## 2. 运行

```bash

git pull
cd stage0/09-rl

```
不用读任何文件。

## 3. 程序的结构

| 行 | 做什么 |
|---|---|
| 20～30 | 可以改的参数 |
| 48～57 | 出题、打分（检查程序） |
| 60～64 | 先检查打分规则对不对：`"答案是 2183"` 不给分，因为开头不是数 |
| 79～92 | `write`：写答案。`sample=True` 抽签（训练用），`False` 每次选分数最高的 token（考试用） |
| 96～109 | 训练前考试 |
| 118～121 | 环节 1：出题，加法、乘法轮流 |
| 123～125 | 环节 2：同一道题写 16 次 |
| 127～132 | 环节 3：打分，减去平均分。16 个全对或全错时记一次「学不到」 |
| 134～161 | 环节 4、5、6 |
| 163～ | 汇总，然后训练后考试 |

## 4. 屏幕上看哪一行

- 第 2 行：一道题变成哪几个 token。
- 训练前考试：加法、乘法各对了几道，以及前 3 道写出了什么。
- 每一步一行：`step 题目和正确答案 16 个里对的比例 | 6 个环节的 ms | 显存峰值`。每 10 步多一行：这一组 16 个答案。
- 汇总：加法、乘法分开看，前一半和后一半对的比例；「全对或全错、什么也学不到的步数」；6 个环节的时间。
- 最后：训练后考试。

## 5. 运行之前，请先预测（不用算）

2. 「什么也学不到的步数」主要出在加法题还是乘法题？
3. 训练后考试，乘法会比训练前对得多吗？

# 第 9c 步：先写过程，再写答案（rl_math_steps.py）

代码：[rl_math_steps.py](rl_math_steps.py)。用户 10-28 的要求：要学会过程，不是猜数字。

## 1. 和 9b 比

| | 9b rl_math.py | 9c rl_math_steps.py |
|---|---|---|
| 题目前面 | 什么也没有 | 2 个写过程的例子（第 35～36 行） |
| 模型写什么 | 直接写答案 | 照例子写过程：`37×46=37×40+37×6=1480+222=1702` |
| 打分 | 答案对 1 分 | 用 `=` 分开，**每一段** Python 都算一遍，都等于正确答案，才得 1 分（第 63～79 行） |
| 每个答案多长 | 8 个 token | 48 个 token |
| 考试 | 对了几道 | 分开数：「答案对」几道，「过程和答案都对」几道 |

打分规则先检查了 6 个例子（第 82～87 行）：例如 `37×40+37×6=1480+232=1702` 答案对，但是 1480+232 不等于 1702，得 0 分。

## 2. 运行

```bash

git pull
cd stage0/09-rl
python rl_math_steps.py
```

## 3. 运行之前，请先预测（不用算）

2. 「答案对」和「过程和答案都对」，哪个多？
3. 每一步的时间，比 9b（1499 ms）多还是少？

## 4. 跑完以后，一次只改一个参数

| 改什么 | 改成 | 先预测 |
|---|---|---|
