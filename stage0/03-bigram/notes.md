## 代码导读：[bigram_tang.py](bigram_tang.py)

| 位置 | 做什么 |
| --- | --- |
| `download` | 从 chinese-poetry 项目下载全唐诗 58 个 json，丢掉有缺字标记的诗，繁转简，每首一行存成 `data/tang.txt`。第 4、5 步都用这份数据 |
| 第 3 段 | 词表：所有出现过的字排个序编号，换行符也算一个"字"，表示一首诗结束 |
| 第 4 段 | 整个模型就是 `nn.Embedding(V, V)`：一张 8182×8182 的表，第 i 行是"前一个字是 i 时，下一个字的分数" |
| `get_batch` | 随机抽 batch 段连续文字，标签 y 是 x 整体右移一位：每个位置都在猜下一个字 |
| `generate` | 分数除以温度再 softmax，按概率抽一个字，抽到换行就停 |
| 第 6 段 | AdamW 训练，定期打印训练、验证 loss |

## 读出来的结论

1. **未训练比瞎猜还差**：随机初始化不是均匀地猜，而是随机偏向某些字，所以 9.55 > 9.01。
2. **loss 卡在 5.27 是模型能力到顶，不是训练不够**：只看前一个字，"月"后面接"明""光""下""色"都常见，永远分不清。和"螺旋 + 2 个神经元"是同一类问题。
3. **困惑度**：e^5.27 ≈ 194，相当于每个字在约 194 个候选里犹豫；验证集 e^6.44 ≈ 626。
4. **训练 5.27 / 验证 6.44 差距大**：很多两字组合在训练集只出现一两次，被大表背下来了，是过拟合。
5. **参数多不等于聪明**：6700 万参数，是 MNIST 网络的 660 倍，比第 4 步的小 GPT 还多，但写不出通顺的句子。结构决定能力。

## temperature 对比

- **0.1**：几乎总选最可能的字。"春"后面最常见的是句号，所以一个字就结束：`春。` `月，一曲，不知。`
- **1.0**：两字之间读得通（何处、惜别、红烛、余霞、繁华、山河），整句不通，数不了五言七言，因为它不记得已经写了几个字。
- **2.0**：概率被拉平，冷僻字也被选中，变成乱码。

实际 LLM 服务的温度一般在 0.6～1.0。

## 留给第 4 步的对比基准

同一份唐诗，小 GPT 的验证 loss 要和 **6.44** 比。

## 检验题：生成 20 个字要几次前向？

- 20 次（标点也是 token，算上标点会更多），只能串行：第 2 个字的输入就是第 1 个字的输出，不知道第 1 个字就没法算第 2 个。
- 这和有没有注意力无关，GPT 生成时一样要一个一个来。这就是 LLM 推理里 decode 慢的根源。
- 训练却可以并行：所有正确答案都已知，一段文本里每个位置"预测下一个字"可以同时算。推理时一次性处理用户输入的 prompt（prefill）也是并行的。
