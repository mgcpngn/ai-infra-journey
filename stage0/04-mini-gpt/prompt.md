# 第 4 步：小 GPT 写唐诗

## 这一步要搞懂的
- 注意力：每个字怎么"看"前面所有的字
- Transformer 块 = 注意力 + MLP，叠很多层就是 GPT
- 同一份数据、差不多的参数量，换个结构，效果差多少
- 训练可以并行，生成只能一个字一个字来

## 给本机 Claude Code 的提示词

```
先用大白话讲这个实验在干什么、每个参数的含义，再写代码。

在第 3 步 bigram 的基础上（同一份 data/tang.txt、同一个按字建的词表），用 PyTorch 从零写一个小 GPT（参考 nanoGPT 的结构，不要直接 import 现成的 GPT 库），在我的 RTX 4060（8GB）上训练。要求：

1. 结构：embedding + 位置编码 → N 个 Transformer 块（每块：LayerNorm → 多头因果自注意力 → LayerNorm → MLP）→ LayerNorm → 输出层。默认 6 层、6 个头、每个字用 384 个数表示、一次最多看 128 个字。这些都做成命令行参数。
2. 打印参数量，并按 embedding、注意力、MLP、输出层分别列出各占多少。
3. 训练：AdamW，bf16 混合精度，每隔一段打印训练和验证 loss，以及每秒处理多少个 token。默认 5000 步。验证 loss 要和第 3 步 bigram 的 6.44 对比。
4. 生成：给一个开头字，temperature 默认 0.8，生成 5 首诗。
5. 测生成速度：分别生成 50、200、500 个字，打印总耗时和平均每个字的耗时。先不要用 KV cache。
6. 保存训练好的模型到 checkpoints/，下一步要用。
```

## 跑完后要能回答的问题
1. 验证 loss 是多少？比 bigram 的 6.44 低了多少？参数量和 bigram 比谁多？
2. 参数量里 embedding、注意力、MLP、输出层各占多少？哪部分最大？
3. 生成的诗能不能数对五言、七言？为什么 bigram 做不到而它能做到？
4. 训练时每秒能处理几千个 token，生成时每秒才几十个字，为什么差这么多？
5. 生成 500 个字时，平均每个字的耗时比 50 个字时长还是短？为什么？（这是第 5 步 KV cache 要解决的问题）
