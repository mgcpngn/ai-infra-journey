## BATCH = 16，L = 32（10-26）
猜下一个字 177.9 / 算 loss 7.8 / 算梯度 225.0 / 改参数 9.8 / 合计 421.2 ms。峰值 3386 MB，临时用的 2196 MB（L=64 时 4267），数字表 11 MB。
用户预测：峰值变小（对，临时显存约一半）；时间变成 1/2（错：反而从 322 变成 421 ms）。
待查：没变一半推测是每层固定的启动时间；变慢原因不明。L=64 重跑 314.6 ms（和第一次一样），电脑没变慢；L=32 待重跑。
L=32 重跑：合计 451.5 ms（猜 194.3、算 loss 7.9、算梯度 239.6、改参数 9.0），几乎每一步都慢，确认不是碰巧。
线索：改参数的活和 L 无关，却从 6.5 变成 9.0 ms；第 8 步合计 266 ms 时改参数 4.1 ms——5 个环节一起快、一起慢。
推测：活太少时笔记本 GPU 不升频。待用 nvidia-smi 看 clocks.sm 和 utilization.gpu 验证。

## GPU 频率和占用（nvidia-smi，每秒一行，10-26）
| | clocks.sm | utilization.gpu |
|---|---|---|
| L=64 | 大多 2310～2640 MHz | 大多 30%～67% |

结论（推测，数据对得上）：L=32 活少，GPU 多数时间在等，笔记本降频，5 个环节一起变慢。
L=64 时 GPU 也只忙一半左右：推测在等 CPU 发下一个计算。训练时这张卡没吃饱。
测性能时要同时记 GPU 频率和占用。

## R = 32（BATCH 16，L 64，10-26）
要训练的参数 9,175,040（1.539%），+35 MB。合计 461.7 ms（猜 189.8、算 loss 15.1、算梯度 246.7、改参数 9.3）。峰值 5557 MB（r=8 时 5468），LoRA 和 AdamW 121 MB（r=8 时 43）。
显存几乎不变：旁路比主路和临时显存小很多。时间待对照：L=32 两次也约 450 ms，第 17 步 268 ms，可能是降频。请用户挨着跑 R=8 / R=32 并开 nvidia-smi。

## 第 8 步结论（10-26）
1. 时间：算梯度最多（约 54%），猜下一个字其次（约 40%），挑数据、改参数几乎不花时间。
2. 显存：训练一步中间临时用的（约 4.3 GB）是模型本身（1.1 GB）的约 3.5 倍；猜完后最高，算完梯度就放掉。
3. batch：16 → 24 → 32，峰值 5.5 → 7.6 → 9.7 GB。超过 8 GB 不报错，而是放到电脑内存里，慢 16 倍。最好的 batch 是完全放进显存、留余量的那个。
4. GPU 只忙一半左右；活太少时笔记本还会降频（L=32 反而更慢）。测性能要同时记频率和占用。
5. r 变成 4 倍，显存只多 89 MB：旁路很小。r 对时间的影响因为降频没测准，不再追。
